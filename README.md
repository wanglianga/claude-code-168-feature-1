# 农村集市摊位抽签收费食品留样与投诉平台

面向乡镇集市的一体化管理平台，覆盖 **报名 → 审核 → 抽签 → 缴费 → 入场核验 → 巡查 → 食品留样 → 投诉处理 → 信用与调整追溯 → 复盘看板** 全链路。

- 后端：Spring Boot 3 + Spring Security(JWT) + Spring Data JPA
- 前端：Vue 3 + Vite + Element Plus + ECharts
- 数据库：PostgreSQL

## 角色与功能

| 角色 | 功能 |
| --- | --- |
| 摊主 VENDOR | 赶集日前报名（品类/车辆尺寸/用电/是否熟食活禽/证照照片/历史经营记录）、查看抽签结果与入场码、缴费、上传食品留样（照片/批次/保存位置）、**处理雨天临时调位通知（查看受影响情况/可替代硬化路面位置/消防通道距离/邻摊影响/收费差额，确认后获取重新生成的入场二维码与差额账单；拒绝时选择放弃经营或保留原位风险自担）**、查看信用与调整记录、提交申诉（费用/扣罚/边界争议） |
| 市场工作人员 STAFF | 扫码入场核验并拍摄摊位布置、登记实际品类与是否按位摆摊、巡查登记（卫生/明码标价/缺斤少两/占道/用电安全） |
| 乡镇管理员 ADMIN | 集市与摊位区域管理（**标注硬化/低洼路面、应急备用位、消防通道距离与平面坐标**）、报名审核、组织抽签（种子+规则快照留档、一键复核）、**雨天临时调位（扫描积水受影响摊位→匹配硬化路面候选位并展示消防通道距离/邻摊影响/收费差额→发起调位单→摊主确认后上传新摊照片归档→向财务推送新旧照片/摊主确认/收费差额并核销应退款；摊主拒绝时标记放弃经营或风险自担）**、投诉处理（可联动信用扣分）、调整（临时调位/雨天调位/费用减免/保证金扣罚/信用调整/品类变更，原因与来源必填）、复盘看板（高投诉品类/拥堵区域/收费到账/食品安全风险）、审计日志 |
| 消费者（免登录） | 凭摊位号提交投诉（腹泻/价格/缺斤少两等） |

## 公平与可追溯设计

1. **抽签可复核**：抽签算法为确定性算法——同一「输入快照 + 随机种子」重放结果必然一致。每次抽签固化规则快照与输入快照，管理端提供「复核」按钮重新演算比对，防止结果被篡改。
2. **规则内置**：老摊主（历史经营≥3次且信用≥60）优先；熟食仅入冷链区（有电源）；活禽仅入隔离区；用电需求仅配有电源摊位；车辆超限排除；消防通道等停用摊位不参与分配。
3. **调整必留痕**：临时调位、费用减免、保证金扣罚、信用调整、品类变更均必须填写**原因**与**来源**（雨天/投诉/巡查/争议/摊主申请/政策），生成 Adjustment 记录并写审计日志，摊主端可见，避免"规则被人为改变"的质疑。
4. **全链路审计**：抽签、审核、核验、巡查、投诉处理、调整等敏感操作全部写入审计日志。

## 雨天临时调位（赶集日清晨暴雨场景）

低洼泥地摊位清晨积水时，平台按"**扫描 → 评估 → 协商 → 调位 → 归档 → 对账**"闭环处理，全程留痕、摊主知情确认：

1. **受影响摊位**：管理员在「雨天临时调位」选择集市，平台自动列出低洼（非硬化路面）已分配摊位；摊位是否硬化、平面坐标在「区域摊位管理」中维护。
2. **可替代位置与安全评估**：对每个受影响摊位，平台只列出**硬化路面、兼容（品类区域/熟食冷链/活禽隔离/用电/车长）且未被占用**的摊位（含应急备用位，应急位不参与常规抽签），并逐项展示：
   - **距消防通道距离**（取摊位登记值，否则按平面坐标到消防通道计算，<3 米给出红色预警）；
   - **邻摊影响**：新摊周边 5 米内现有摊位的摊主、品类、间距；
   - **收费差额**：按新旧区域摊位费（含电费）自动计算，正数补收、负数应退。
3. **摊主确认**：发起调位必须填写调位原因（向摊主公开）与原摊位积水照片；摊主在「雨天调位通知」查看全部信息后：
   - **同意** → 系统即时调换摊位、按新区域错峰时间更新入场时间、**重新生成入场二维码（旧码作废）**、重建收费项目快照，并按差额生成 `FEE_DIFF`（补收）或 `FEE_REFUND`（应退）账单，摊主可出示新码核验入场；
   - **拒绝** → 必须二选一：**放弃本场经营**（分配单取消）或**保留原位、风险自担**（决定写入调整追溯，留痕可查）。
4. **归档与财务**：摊主同意后管理员补传新摊位（硬化路面）布置照片归档；「财务对账」页向财务展示**新旧摊位照片、摊主确认（时间/备注）、收费差额与账单状态**，应退款由财务一键核销为已退还。
5. 调位、放弃、风险自担均生成 `Adjustment` 追溯记录（来源 RAIN + 调位单号）并写审计日志，摊主端「信用与追溯」可见。

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

- 前端：http://localhost （80 端口）
- 后端：http://localhost:8080
- 数据库：PostgreSQL localhost:5432（market / market123）

首次启动自动建表并初始化演示数据（账号、区域摊位、一个报名中的集市）。摊位按"硬化路面/低洼泥地"区分：A/B/C/E 区为硬化路面（E 区为不参与抽签的雨天应急疏导区），**D 区果蔬区为低洼泥地**，可直接演示雨天调位。

## 本地开发

```bash
# 1. 准备 PostgreSQL（建库 market，用户 market/market123），或用 docker 单起数据库：
docker run -d --name market-db -p 5432:5432 \
  -e POSTGRES_DB=market -e POSTGRES_USER=market -e POSTGRES_PASSWORD=market123 postgres:16-alpine

# 2. 后端（默认连 localhost:5432/market，可用 DB_URL/DB_USER/DB_PASSWORD 覆盖）
cd backend && mvn spring-boot:run

# 3. 前端（Vite 代理 /api 与 /files 到 8080）
cd frontend && npm install && npm run dev   # http://localhost:5173
```
