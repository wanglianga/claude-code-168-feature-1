# 农村集市摊位抽签收费食品留样与投诉平台

面向乡镇集市的一体化管理平台，覆盖 **报名 → 审核 → 抽签 → 缴费 → 入场核验 → 巡查 → 食品留样 → 投诉处理 → 信用与调整追溯 → 复盘看板** 全链路。

- 后端：Spring Boot 3 + Spring Security(JWT) + Spring Data JPA
- 前端：Vue 3 + Vite + Element Plus + ECharts
- 数据库：PostgreSQL

## 角色与功能

| 角色 | 功能 |
| --- | --- |
| 摊主 VENDOR | 赶集日前报名（品类/车辆尺寸/用电/是否熟食活禽/证照照片/历史经营记录）、查看抽签结果与入场码、缴费、**雨天调位通知（确认/拒绝）**、上传食品留样（照片/批次/保存位置）、查看信用与调整记录、提交申诉（费用/扣罚/边界争议） |
| 市场工作人员 STAFF | 扫码入场核验并拍摄摊位布置、登记实际品类与是否按位摆摊、巡查登记（卫生/明码标价/缺斤少两/占道/用电安全） |
| 乡镇管理员 ADMIN | 集市与摊位区域管理、报名审核、组织抽签（种子+规则快照留档、一键复核）、投诉处理（可联动信用扣分）、**雨天临时调位（受影响摊位/替代位置/消防通道距离/邻摊影响 → 摊主确认 → 财务核对）**、调整（临时调位/费用减免/保证金扣罚/信用调整/品类变更，原因与来源必填）、复盘看板（高投诉品类/拥堵区域/收费到账/食品安全风险）、审计日志 |
| 消费者（免登录） | 凭摊位号提交投诉（腹泻/价格/缺斤少两等） |

## 公平与可追溯设计

1. **抽签可复核**：抽签算法为确定性算法——同一「输入快照 + 随机种子」重放结果必然一致。每次抽签固化规则快照与输入快照，管理端提供「复核」按钮重新演算比对，防止结果被篡改。
2. **规则内置**：老摊主（历史经营≥3次且信用≥60）优先；熟食仅入冷链区（有电源）；活禽仅入隔离区；用电需求仅配有电源摊位；车辆超限排除；消防通道等停用摊位不参与分配。
3. **调整必留痕**：临时调位、费用减免、保证金扣罚、信用调整、品类变更均必须填写**原因**与**来源**（雨天/投诉/巡查/争议/摊主申请/政策），生成 Adjustment 记录并写审计日志，摊主端可见，避免"规则被人为改变"的质疑。
4. **雨天临时调位全流程**：摊位登记「低洼易积水/硬化路面/距消防通道距离」属性。暴雨时管理端「雨天临时调位」自动列出**受影响摊位**（已分配的低洼摊位），并为每个摊位给出**可替代位置**（硬化路面、空闲、品类/用电/车长兼容），同时展示**消防通道距离**与**邻摊影响**（左右邻摊占用与品类冲突提示）。发起后生成待确认工单 → 摊主在「雨天调位通知」**确认**后系统**重新生成入场二维码**并按新旧区域摊位费差额生成**收费差额单**（正=摊主补缴，负=财务退还）→「财务核对」页向财务展示**新旧摊位照片、摊主确认记录与收费差额**（负差额可标记已退还）。摊主**拒绝**的，管理员可标记**放弃经营**（取消分配、未缴账单作废）或**保留原位风险自担**。全程生成 Adjustment（来源=雨天）与审计日志。
5. **全链路审计**：抽签、审核、核验、巡查、投诉处理、调整、雨天调位等敏感操作全部写入审计日志。

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

- 前端：http://localhost （80 端口）
- 后端：http://localhost:8080
- 数据库：PostgreSQL localhost:5432（market / market123）

首次启动自动建表并初始化演示数据（账号、区域摊位、一个报名中的集市）。

## 本地开发

```bash
# 1. 准备 PostgreSQL（建库 market，用户 market/market123），或用 docker 单起数据库：
docker run -d --name market-db -p 5432:5432 \
  -e POSTGRES_DB=market -e POSTGRES_USER=market -e POSTGRES_PASSWORD=market123 postgres:16-alpine

# 2. 后端（默认连 localhost:5432/market，可用 DB_URL/DB_USER/DB_PASSWORD 覆盖）
cd backend && mvn spring-boot:run

# 3. 前端（Vite 代理 /api 与 /files 到 8080）
cd frontend && npm install && npm run dev   # http://localhost:5173
```

## 本题验证方式（完整业务闭环）

1. **报名**：用 vendor1~vendor6 登录 →「摊位报名」选择"十月十五大集"提交（品类/车辆/用电/熟食活禽/证照照片/历史记录）。
2. **审核**：admin 登录 →「集市与报名审核」→ 报名审核 → 全部通过。
3. **抽签**：admin → 集市列表"截止报名"→"组织抽签"输入种子执行；「抽签管理」查看结果明细与规则/输入快照，点"复核"应显示**复核通过**。
4. **缴费**：vendor1 →「抽签结果与缴费」查看摊位号/入场时间/收费项目/保证金/禁止事项/入场码，缴纳费用。
5. **入场核验**：staff1 →「入场核验」输入摊主入场码 → 确认实际品类、按位摆摊、上传布置照片。
6. **巡查**：staff1 →「巡查登记」对摊位登记卫生评分、明码标价、缺斤少两、占道、用电安全。
7. **留样**：vendor1（熟食）→「食品留样」上传留样照片、批次、保存位置。
8. **投诉**：访问 /complaint（免登录）凭摊位号提交"腹泻"投诉；admin →「投诉处理」办结并联动扣信用。
9. **调整追溯**：admin →「调整与追溯」发起临时调位/费用减免/保证金扣罚/信用调整（原因+来源必填）；vendor1 →「信用与追溯」可见全部调整的原因与来源。
10. **雨天临时调位（本题）**：
    - 准备：抽签结果中果蔬摊主分入 D 区（D-01~D-04 为低洼未硬化摊位）；若果蔬摊主未分到低洼摊位，admin →「调整与追溯」用"临时调位"将其调入 D-01~D-04 任一低洼位即可模拟。
    - 发起：admin →「雨天临时调位」→ 发起调位 Tab 展示**受影响摊位**（低洼）→"选择替代位置"展示**硬化路面替代位、消防通道距离、邻摊影响**→ 上传新旧摊位照片、填写积水原因 → 发起（状态：待摊主确认）。
    - 确认：vendor4（赵四）→「雨天调位通知」→ 查看新旧摊位/差额/消防距离/邻摊影响 →"确认调位"→「抽签结果与缴费」可见**新入场二维码已换发**、差额账单已生成（正差额在线补缴）。
    - 财务：admin →「雨天临时调位」→ 财务核对 Tab 查看**新旧摊位照片、摊主确认记录、收费差额**；负差额（应退摊主）可"标记已退还"。
    - 拒绝分支：对其他受影响摊位发起调位后，摊主"拒绝调位"（必填说明）→ admin 在调位单管理 Tab 标记**放弃经营**（分配单取消、未缴账单作废）或**保留原位风险自担**（分配不变、留痕）。
11. **复盘**：admin →「复盘看板」查看高投诉品类、拥堵/占道区域、收费到账、食品安全风险；「审计日志」查看全部敏感操作留痕。

- 后端连本地 PostgreSQL 15 实启动成功，种子数据自动初始化（含摊位低洼/硬化/消防距离属性）。
- 通过 curl 完成两轮完整业务闭环接口级冒烟：
  - 第一轮：6 家报名→审核→抽签（种子 20261015）→**复核一致(match=true)**→缴费→扫码→入场核验→巡查→留样→公开投诉→投诉处理联动扣信用→雨天调位（目标摊位占用校验生效）→费用减免→保证金扣罚→看板统计与审计日志均返回正确数据。
  - 第二轮（经前端代理端口）：新集市开放报名→2 家报名→审核→截止→抽签→复核通过；果蔬摊主分入 D 区、用电百货摊主分入 A 区带电摊位，区域/用电约束生效。
- **雨天临时调位专项冒烟（本轮，curl 全通过）**：
  - 受影响摊位列表正确列出低洼摊位（赵四 D-01），11 个替代位置均含**消防通道距离**与**邻摊影响**说明，且只含硬化路面、品类兼容、未被占用的摊位。
  - 赵四确认调位（D-01→A-05，差额+5）：**入场二维码重新生成**（新旧 token 不同）、分配单状态 RELOCATED、收费项目快照更新为新区费用、差额账单生成并在线缴清（PAID）。
  - 钱五确认调位（A-02→D-06，差额-5）：负差额账单生成，财务核对页"标记已退还"后状态 REFUNDED。

  - 张老三拒绝调位 → 管理员标记**放弃经营**：分配单 CANCELLED，全部未缴账单作废（WAIVED）。
  - 财务核对接口返回已确认调位的**新旧摊位照片、摊主确认时间与备注、收费差额及差额单状态**。
  - 每张工单均生成 Adjustment（type=RAIN_RELOCATE、source=RAIN、sourceRefId=工单号）与审计日志（发起/确认/拒绝/处理/退还五类动作），摊主端「信用与追溯」可见。

- 安全校验：未登录访问管理接口返回 403、摊主访问管理接口返回 403、响应不返回密码字段（@JsonIgnore）。
- 文件上传（证照/留样/调位照片）与 /files 静态访问验证通过。
